# Morrow v2.4.1 — Morrow Unified License, and the attributions that go with it

**Release date:** 2026-11-01
**Toolchain:** `forge 2.4.1 (morrow standalone 2026)`
**Self-hosting fixed point:** `C19556C9FC83B8A7A62876D0E21D8D182AD81EA64F71666F1B7376F3A0CDCCB9`
(`target/stage2.exe.ll` == `target/stage3.exe.ll`)

This is a licensing release. There is **no compiler behaviour change**: the entire
diff under `compiler/` is the version literal (`forge 2.4.0` → `forge 2.4.1`), which
is also why the fixed point hash differs from v2.4.0's. Everything else here is
provenance.

## 1. One license instead of three

`LICENSE`, `LICENSE-MIT` and `LICENSE-APACHE` are gone; **`LICENSE.md` — the Morrow
Unified License (MUL) v1.0** — governs the project from this release onward.

The MUL is version-scoped (§1):

- **v0.1 – v2.4.0** remain dual-licensed **MIT or Apache-2.0**, at the recipient's
  choice; those grants are not retroactively changed.
- **v2.4.1 and later** are governed by the MUL.

## 2. Third-party attribution now ships with the artifacts

MUL §10 requires that, "Where third-party components are distributed alongside
Morrow, their applicable license information must be preserved." The distribution
archive carries a full MinGW-w64 + GCC runtime in `lib/crt/`, so that obligation was
real and previously unmet in a machine-readable form.

New `THIRD-PARTY-NOTICES.md` maps every bundled component to its upstream license:

| Component | Files | License |
|---|---|---|
| GCC runtime | `libgcc.a`, `libgcc_eh.a`, `libgcc_s.a`, `libstdc++.a` | GPL-3.0-or-later with the **GCC Runtime Library Exception 3.1** |
| mingw-w64 CRT + Windows import stubs | `crt2.o`, `dllcrt2.o`, `libmingw32.a`, `libmingwex.a`, `libmsvcrt.a`, `libkernel32.a`, … | ZPL 2.1 (with public-domain / BSD / LGPL parts, as marked upstream) |
| GNU libiconv | `libiconv.a` | LGPL-2.1-or-later |
| SQLite | `libsqlite3.a` | Public domain |

`licenses/` now contains the **verbatim texts**: `GPL-3.0.txt`, `LGPL-2.1.txt`,
`ZPL-2.1.txt`, and `GCC-RUNTIME-LIBRARY-EXCEPTION-3.1.txt` (taken from gnu.org and
the GCC source tree, not retyped). `.gitattributes` pins them with `-text` so no
line-ending conversion rewrites them.

The notices also state the two consequences that matter for binaries: the GCC RLE
expressly permits shipping compiled executables without affecting their own
licensing, and the mingw-w64 runtime's ZPL conditions are satisfied by retaining the
notices that now ship alongside the compilers.

## 3. The pipeline refuses to package an archive without them

`stage_verify` opens the produced zip and fails the release if it does not contain
`Morrow/LICENSE.md`, `Morrow/THIRD-PARTY-NOTICES.md` and the upstream texts. This
release's own run reports:

```
Licensing present in Morrow-v2.4.1-win64.zip: LICENSE.md, THIRD-PARTY-NOTICES.md and 4 upstream texts
```

The packaging include list was also corrected — it still asked for the deleted
`LICENSE`, `LICENSE-MIT`, `LICENSE-APACHE` and would have produced an archive with
no license at all.

## 4. Documentation drift fixed

- `README.md`'s repository tree still listed `LICENSE.md` as the "Morrow Triumvirate
  License" plus three files that no longer exist (`MORROW-USE-LICENSE.md`,
  `MORROW-CONTRIBUTOR-LICENSE-AGREEMENT.md`,
  `MORROW-FORK-AND-REDISTRIBUTION-AGREEMENT.md`). It now lists the MUL, the notices
  and `licenses/`.
- `RELEASE_PROCESS.md` documents the new archive layout, the verification rule, and
  one trap: `LICENSE.md` must **not** join the automatic version-bump list — its
  "effective for v2.4.1 and later" is a historical boundary, not a release number to
  follow.
