# Morrow v2.4.9 — `forge argkinds`: measuring what argument type checking would cost

**Release date:** 2026-11-02
**Toolchain:** `forge 2.4.9 (morrow standalone 2026)`
**Self-hosting fixed point:** `B97E2C2EC152E9A1C6E75E4AF06E9BE6FF3909A467FBEBBD6B806FD41C89E5ED`
(stage2.ll == stage3.ll, stage2.exe == stage3.exe, 466944 bytes)

No language behaviour changed. This release adds the instrument that the argument-type
work needs, and publishes its first reading.

## The instrument

```
forge argkinds <file>
```

Runs the typechecker with a report flag: at every call site it compares the **declared
parameter kind** with the **inferred argument kind** and prints

```
ARGKIND want=struct got=ref :: vec_push
```

It never rejects anything and never changes an exit code for a valid file — the flag is
`TypeChecker.arg_report`, off for `check`/`build`/`run`/`lsp`, on only for this
subcommand. `typecheck_program` gained the parameter; all twelve existing call sites
pass `0`.

## The reading

Over `compiler/main.mw` — which loads the whole compiler plus the stdlib it imports —
**1882 discrepancies**, distributed like this:

| Count | Pattern | Reality |
|---|---|---|
| 1538 | `want=struct got=ref` | `vec_push(&mut v, x)`, `hashmap_insert(&mut m, k, v)`: parameter is `Vec<T>`, argument is `&mut Vec<T>` — no reference-of-struct unwrapping exists |
| 103 | `want=struct got=int` | generic `T` resolves to `int` |
| 77 / 73 / 61 | `int` ↔ `String` ↔ `struct` | `T` substitution and call-result inference |
| 13 / 12 / 4 | `u8`↔`ptr`, `bool`↔`int` | literal/bool kind lost through variables |

The practical conclusion, recorded in `ROADMAP.md` 14.5: a kind-equality rule would
reject ~1882 valid call sites in Morrow's own source. **One** missing rule —
unwrapping `&T`/`&mut T` against a `T` parameter — accounts for **82%** of findings, so
the next step is that unwrapping plus literal-kind preservation, then re-measure. The
"152 false positives" figure from the earlier attempt was measured on a smaller corpus;
the real order of magnitude is an order larger.
