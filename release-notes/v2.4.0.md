# Morrow v2.4.0 — Region expressions are typed, field stores are checked

**Release date:** 2026-11-01
**Toolchain:** `forge 2.4.0 (morrow standalone 2026)`
**Self-hosting fixed point:** `0804758B67F7EC80EC39F4B607B32EA3D2F80AC8DD12B314612B0BFC4FA2DE07`
(`target/stage2.exe.ll` == `target/stage3.exe.ll`)

v2.2.0 made the typechecker tag region-scoped values from *allocation*, and
`docs/SYNTAX.md` §4 has been honest ever since about three patterns it could not
see. Two of them are gone in this release, and closing them exposed a parser defect
that could hang the compiler.

## 1. Region expressions are now typed

`let v = region r { … };` was parsed, lowered and executed — but never *typed*.
`tc_expr` took `vars: &HashMap`, so it could not recurse into `tc_stmt` and fell
through to its `i64` default. A region expression's value therefore carried no tag,
and `let v = region r { vec_new_in(r) }; return v;` compiled cleanly while handing
back a dangling pointer.

`tc_expr` now takes `vars: &mut HashMap` and `ret_ty: *mut TcType`. The region case
binds the region name inside its own body (so `vec_new_in(r)` resolves), types the
body statements through `tc_stmt` at region depth +1, and tags the tail value when
it is a pointer/reference or an allocator result. `stmt_let` copies an inherited tag
onto the binding.

The escape checks also stopped being gated on `region_depth > 0`: a tag produced by
a region *expression* must still be honoured when the value is returned or assigned
**after** the region has closed. Tagging stays gated, so arena handles passed as
parameters are unaffected.

## 2. Struct-field stores are rejected

`region r { let p = morrow_region_alloc(r, 8, 8); outer.field = p; }` used to be
invisible: `stmt_field_assign` typed the base and the right-hand side and threw the
types away. It now checks them, resolving the **root** of the field chain so
`a.b.c = p` is attributed to `a`:

```
Region Escape Violation: region-scoped value stored in field of outer-scope value
```

A holder that is itself region-scoped (`out.p = p` where `out` lives in the same
region) is still accepted — the store is confined, not an escape.

## 3. A malformed struct field could hang the compiler

Found while writing the field-store test. `parse_struct`'s field loop ran
`expect(ident)` → `expect(':')` → `parse_type`, none of which consume a token on
mismatch. Writing `p: i64;` (semicolon instead of comma) made the loop spin forever
emitting an unbounded stream of identical diagnostics — it looked exactly like a
hang, and it OOM'd the process. The loop now records its start position, and an
iteration that consumes nothing reports `Malformed struct field; expected
\`name: type,\`` once and advances one token. `forge check` on such a file now
returns three diagnostics and exits.

## What is still not detected (stated, not hidden)

| Gap | Why |
|---|---|
| Indirect escape: `region r { let v = vec_new_in(r); take(&v); }` where `take` stores or returns it | No interprocedural analysis |
| Indexed store: `region r { let p = …; outer_vec[0] = p; }` | `stmt_index_assign` has no holder check yet |

`docs/SYNTAX.md` §4 carries the full detection matrix — eleven rows, each pinned by
a test.
