**Release date:** 2026-11-02

Still diagnostic-only: `check`/`build`/`run` behaviour is unchanged. What changed is that
the instrument is now *correct enough to trust*, and its headline number collapsed for
the right reason.

## The rule, deliberately narrow

The comparison dereferences **at most one level**, and **only** when the parameter is not
itself a reference — because a by-value parameter accepts `&x` / `&mut x`. `&&T` against
`T` therefore stays reported. Nothing is rewritten in the type model: `ty_ref` keeps its
referent (`TcType.left`) and every other checker rule still sees the reference.

Not a `Vec`/`HashMap` special case: the corpus tests references to a user struct and to a
scalar.

## The corpus (`tests/argkinds/`)

Five cases that pin what the instrument must say, so a zero count can't be earned by an
over-permissive inference system:

| Case | Must | Reading |
|---|---|---|
| `&Probe` → by-value `Probe` | silent | silent ✅ |
| `"hello"` → `i64` | reported | `want=int got=String` ✅ |
| `id::<String>("hi")` | reported, argument side `String` | `want=int got=String` ✅ (parameter side is the substitution gap) |
| `&&Probe` → by-value `Probe` | reported (one level only) | `want=struct got=ref` ✅ |
| `&i64` → `i64` | silent | silent ✅ |

## Two limits stated openly

- **Mutability is not represented.** `&T` and `&mut T` are both `ty_ref` today, so no rule
  here can distinguish them — and none pretends to. Distinguishing them is a prerequisite
  for any enforced rule that talks about mutability.
- **The comparison is kind-level.** `struct` vs `struct` never clashes, so `Vec` passed
  where `HashMap` is expected is not reported until substitution makes a `sym` comparison
  meaningful.

## Landing order recorded in ROADMAP 14.5

1. **diagnostic** — done (v2.4.9, corrected in v2.4.10);
2. **experimental enforcement** — reject behind a dedicated flag (not started);
3. **default enforcement** — only after the corpus is trusted *and* negative tests prove
   genuinely invalid calls are rejected. Zero findings is explicitly **not** sufficient.
