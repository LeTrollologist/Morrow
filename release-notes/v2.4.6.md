# Morrow v2.4.6 — GitHub stops building; every release has a record

**Release date:** 2026-11-02
**Toolchain:** `forge 2.4.6 (morrow standalone 2026)`
**Self-hosting fixed point:** `D67DE707657DE6BFA52449DE1BB680AFF348AF1E1AACBDDBE89F9B774BB10ECD`
(`stage2.ll == stage3.ll`, `stage2.exe == stage3.exe` byte-for-byte)

## 1. The CI workflow is gone

`.github/workflows/ci.yml` is deleted. It had two problems and no upside:

- **It never ran.** Every job since 2026-10-31 aborted in ~2 s — *"The job was not
  started because your account is locked due to a billing issue."* A red X on every
  push that means nothing is worse than no workflow.
- **It was a weaker duplicate.** Had it run, it would have repeated `forge test`, the
  example builds, `forge bench`, the docs/version rule and bootstrap IR parity — all of
  which the local pipeline enforces, plus four gates CI never had: executable
  byte-equality, archive determinism, licensing presence and the release record.

The rule is now structural: **GitHub never builds this project.** It receives finished
bytes and stores them. Nothing can be gated "by just pushing", because there is nothing
on the other side to run. `make check` is the full verification without publishing;
preflight's host-CLI guard dropped the dead file from its scan list.

v2.3.2 → v2.4.2 were undocumented. They are now recorded — honestly:

Each reconstructed record is marked `"reconstructed": true` and carries

never captured at the time. An asset is listed only if its hash still matched the
surviving `dist/<tag>/SHA256SUMS.txt`; v2.4.2 lists none because its `dist/` was
clobbered while debugging archive determinism, and it says so in
`reconstruction_note`.
