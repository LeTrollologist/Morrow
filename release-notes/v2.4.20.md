# Morrow v2.4.20

Hardening release: parser/LSP safety, collection bounds, benchmark tooling, C ABI,
setjmp interoperability, and safer release publishing.

## Fixes

- **#14 — bounded parser recursion.** Expression, statement, type, and unary
  parsing share a 512-level limit. Excessively nested input reports
  `Parser nesting limit exceeded (maximum 512 levels)` and stops instead of
  overflowing the stack.
- **#15 — unterminated block comments.** The lexer reports
  `Unterminated block comment` at the comment's starting location. Valid multiline
  comments continue to work.
- **#16 — bounded LSP framing.** `Content-Length` is strictly validated, messages
  are capped at 8 MiB, header lines at 255 bytes, and header count at 64. Malformed
  frames produce a JSON-RPC `-32700` error and terminate cleanly.
- **#17 — explicit, non-destructive publishing.** Publish/ship now require
  `--publish`; tag pushes are no longer forced by default; tag format is validated;
  tag conflicts produce clear failures. `RELEASE_PROCESS.md` and the Makefile
  document the behavior.
- **#18 — collection boundary safety.** Invalid `Vec` indices return a zero value
  (or no-op for `vec_set`); invalid capacities and allocation failures are safe;
  HashMap lookup/insert/remove/free handle invalid state predictably. Contracts are
  documented and covered by boundary tests.
- **#19 — benchmark runner repaired.** `benchmarks/bench_runner.py` is valid UTF-8,
  runs `forge bench` from the documented location, propagates failures, and the
  release gate now `py_compile`s every Python helper.
- **#20 — C ABI and setjmp hardening.** Extern declarations use real C types
  (`i32`/`i16`/`i8`/`u8`/`f32`/`f64`/pointers/void), narrow returns are
  sign/zero-extended correctly, structs by value are rejected, and setjmp carries
  LLVM's `returns_twice` attribute. Added FFI + longjmp regression coverage.
