# Morrow v2.3.4 — "main never uses a host CLI", enforced

**Release date:** 2026-11-01
**Toolchain:** `forge 2.3.4 (morrow standalone 2026)`
**Self-hosting fixed point:** `4D04C1829894B750FB5B2726714D47E6B7141F8C1DCFC5257C4516C563B0E717`
(`target/stage2.exe.ll` == `target/stage3.exe.ll`)

v2.3.2 removed the host CLI from the pipeline. That left the rule as a convention:
a reviewer reads the diff, or nothing catches the next `gh release` line. A rule
that can silently come back is not a rule, so it is now checked by the pipeline
itself.

## The guard

Preflight scans the release path — `scripts/pipeline.py`, `Makefile`, and
`.github/workflows/ci.yml` — for host-CLI invocations (`gh`, `glab`, `hub` followed
by a subcommand such as `release`, `auth`, `api`, `repo`, `pr`, `issue`, `workflow`,
`upload`, `secret`, `run`). If one appears, the release **aborts before the build**,
naming file and line:

```
RuntimeError: The release path must not invoke a host CLI (git only). Found:
  Makefile:46: publish-fake: ; gh release create v0.0.0 --notes x
```

That message is not hypothetical — it is the output produced when the guard was
tested by injecting exactly that line into the Makefile. The line was then reverted.

The pattern is deliberately narrow: prose that *mentions* a host CLI (this document,
the pipeline's own comments, `RELEASE_PROCESS.md`) is unaffected. Only an actual
invocation trips it.

## The invariant, stated plainly

- **`main` publishes with `git`.** Commit, annotated tag, push, and independent
  verification via `git ls-remote`. Nothing else.
- **Host CLIs belong to forks.** Someone working from a fork may use `gh` for pull
  requests or to attach assets to their own release page. That is a contributor
  convenience, not a requirement, and it is not part of what `main` does.
- **`RELEASE_PROCESS.md` §3 now carries this as publish rule 5**, with the mechanical
  check described, so the document and the code say the same thing.
