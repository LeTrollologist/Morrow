# Morrow v2.4.11 — Call-site substitution, and the case that keeps it honest

**Release date:** 2026-11-02
**Toolchain:** `forge 2.4.11 (morrow standalone 2026)`
**Self-hosting fixed point:** _(filled by this run)_

Diagnostic-only release, as before: `check`/`build`/`run` are untouched.

## What changed in the instrument

When a declared parameter **is** the callee's generic parameter (`fn id<T>(x: T)`), its
declared kind says nothing — it resolves to `int` today. The report now:

- takes the expectation from the **turbofish instantiation** when the caller supplied one;
- leaves the argument **unreported** when it did not, instead of comparing against a
  placeholder.

That is substitution *at the call site*, not in the type model: nothing about `TcType` or
inference changed.

The residual 229 are the next, different problem: `struct↔int` 124 and `String↔int` 73 —
parameters typed `Vec`/`String` receiving expressions the checker infers as `int` (call
results, struct fields, values out of `vec_get`) — plus `u8↔ptr` 13 and `bool↔int` 12 for
literal kind lost through variables. That is **call-result and field inference**, i.e. the
`ty_int()` fallbacks, recorded in ROADMAP 14.5 as the next target.

## The corpus gained a case that cannot be gamed

`case3` (`id::<String>("hi")`) is now **silent** — correct, because the instantiated
expectation is `String` and the argument is `String`. But silence on its own could be
achieved by simply skipping generic parameters, which would be a lie. So `case3b`
(`id::<i64>("hi")`) requires the opposite:

```
ARGKIND want=int got=String :: id
```

An instantiated parameter whose declared kind is `int` still catches a `String` argument.
The pair is the actual proof that substitution happened rather than being skipped.

## Enforcement

Unchanged and deliberately so. ROADMAP 14.5 keeps the three stages separate:
**diagnostic** (done), **experimental enforcement** (not started), **default enforcement**
(not started, and gated on the corpus plus negative tests — never on a zero count alone).
