# Morrow v2.4.5 — One command: build, verify, tag, push, upload

**Release date:** 2026-11-02
**Toolchain:** `forge 2.4.5 (morrow standalone 2026)`
**Self-hosting fixed point:** _(recorded by this run; see `releases/v2.4.5.json`)_

## What was wrong

After v2.4.4 the pipeline produced a correct release **locally** — tag, archive,
checksums, ledger — and then stopped. The release page was left for a human, so the
Releases list still showed v2.3.1 as latest while eight versions sat in the Tags list.
That is not a release; it is a half-release. Worse, I had claimed the pages would
appear by themselves, which they never would.

## What changed: stage 9, `ship`

The pipeline now finishes the job in the same run:

```
preflight → version → build → test → bench → package → verify → publish → ship
```

`scripts/release_page.py` creates (or updates) the release page for the tag, sets its
body from `release-notes/vX.Y.Z.md`, and uploads everything in `dist/vX.Y.Z/` —
`forge.exe`, `mwc.exe`, `Morrow-vX.Y.Z-win64.zip`, `RELEASE_NOTES.md`,
`SHA256SUMS.txt`. Re-running replaces assets by name, so republication works there
too.

**GitHub is a file host, never a builder.** No Actions workflow runs, no CI runner is
in the path, no forge CLI is invoked: it is a REST call carrying the bytes this
machine compiled, signed off by the checksums it computed. The credential is the one
`git push` already uses (`MORROW_GITHUB_TOKEN` takes precedence). `--no-release-page`
keeps a release local-only, and `make ship` retries the upload alone.

## Guard rails on the upload

- **Nothing unverified ships.** If an artifact's hash disagrees with the
  `SHA256SUMS.txt` beside it, the stage publishes the page *without binaries* and says
  so — a page with notes beats a page with bytes we cannot vouch for. (That is exactly
  what happened for v2.4.2, whose local `dist/` was clobbered while debugging
  reproducibility.)
- **Failure is loud.** A failed upload fails the run; the local release is already
  complete, so `--from ship` retries without rebuilding.
- **Host-CLI guard extended** to `scripts/release_page.py`, so the release path stays
  free of `gh`/`glab`/`hub` by construction.

## Backfill

The eight versions that were tag-only are now published: v2.3.2, v2.3.3, v2.3.4,
v2.4.0, v2.4.1, v2.4.2, v2.4.3, v2.4.4 — each with its notes as the body, and with the
locally built binaries attached wherever the recorded checksums still matched.
